# Qwen3.5-122B-A10B 접기 정확도 캠페인 (2026-07-30 ~ 07-31)

M1 Max 32 GB 에서 Qwen3.5-122B-A10B(78.64 GB)를 그래프 접기로 15.11 GiB 상주 구동한 뒤,
**접기가 깎은 품질을 학습 없이 어디까지 되찾을 수 있는가**를 측정한 캠페인의 전체 기록이다.

**결론부터: 품질 가설은 반증되었다.** 같은 15 GB 예산에서 네이티브 Qwen3.5-35B-A3B 를
그냥 양자화해 쓰는 편이 접힌 122B 보다 모든 측정 축에서 낫다.

## ⚠ 무효 수치 경고

부록 II·III·IV 와 PROGRESS 본문의 **접기 비용·회수율 수치는 프로토콜 오류의 산물**이다.
`llama-perplexity` 의 태스크 선택은 `std::mt19937 rng(1)` 하드코딩이라 400문항 런의
앞 40개와 40문항 런은 동일 문항인데, n=400 접힘 점수에서 n=40 미접힘 점수를 빼서
"접기 비용"을 계산했다.

| 항목 | 무효 기록 | 동일 문항 실측 |
|---|---|---|
| HellaSwag 접기 비용 | 18.25점 | **32.5점** |
| MMLU 접기 비용 | 12.85점 | **17.2점** |
| HellaSwag 회수율 | 55% | **15%** |
| MMLU 회수율 | 11% | **0%** |
| 미접힘 122B vs 네이티브 35B (MMLU) | 122B +4.61 | **35B +0.69** |

## 유효한 결과

1. 저장소 절벽 제거 — 78.64 GB 모델이 15.11 GiB 상주로 구동 (시스템 측)
2. 접기 비용의 존재 — HellaSwag 32.5점, MMLU 17.2점 (동일 문항, n=40/145)
3. 전문가 예산 재배치의 유창성 축 개선 — HellaSwag 대응 McNemar **p=4.7×10⁻⁶**,
   ARC-C **p=0.018** (400/299 문항 전수)
4. 생성형 프로토콜 격차 55pp — 49/60 vs 16/60, Fisher **p=1.7×10⁻⁹**
5. **같은 메모리에서 네이티브 35B 가 접힌 122B 를 전 지표 압도**
6. 핫 전문가 선정의 접기 맵 불변성 — 맵을 바꿔도 겹침 82.5%

## 방법론 (이식 가능한 부분)

- **문항별 정오 복원**: llama.cpp 의 MC/HellaSwag 로그는 누적 정답률을 문항마다 출력한다.
  이를 차분하면 문항별 정오가 복원되어 **대응 McNemar 검정**이 가능하다. 8개 로그 전수
  검증에서 복원값이 보고값과 일치했고 최대 반올림 잔차는 9.8×10⁻⁸(판정 경계의 500만분의 1),
  깨지는 조건은 n ≥ 10^(d+1)(d = 출력 소수 자릿수, 현재 8)이다.
  비대응 z 검정 대비 검출력 차이가 크다 — 같은 비교에서 z=1.86(p≈0.06) vs 대응 p=5.4×10⁻⁴.
- **우도 채점의 한계**: `--multiple-choice` 우도 채점은 정답 토큰의 상대 확률만 본다.
  thinking 기본 생성형 모델에서는 실사용과 어긋나며, 같은 모델 쌍의 격차가
  우도 8.2pp vs 생성형 55pp 로 벌어진다. (선행: LLM-KICK, arXiv:2310.01382)
- **네이티브 대조군 필수**: 같은 하네스로 네이티브 모델을 재지 않으면 하네스 결함과
  모델 손상을 구분할 수 없다.
- **메모리 회계**: wired(시스템 전체)도 RSS(mmap 파일페이지 포함)도 llama 몫이 아니다.
  정확한 값 = GGUF 전체 텐서 바이트 − 로더가 건너뛴 텐서 바이트 (`scripts/memcalc58.py`).

## 재현

모델 파일(약 199 GB)은 연구 종료와 함께 삭제했다. 재현하려면
`unsloth/Qwen3.5-122B-A10B` Q4_K_XL 을 받아 `scripts/` 의 재양자화·수술 스크립트를 순서대로
실행해야 한다. 접기 구현은 llama.cpp 포크 `cornch-k/llama.cpp@6eecc1736`(브랜치 prefill-nanfix).

`scripts/safe.sh` 와 `scripts/queue.sh` 는 이 캠페인 중 커널 패닉(watchdog timeout)을
겪은 뒤 만든 실험 실행 인프라다 — 전역 잠금(shlock)으로 동시 실행을 물리적으로 차단하고,
시스템 전체 스왑·여유율·디스크를 감시한다. 소비자 기기에서 대형 모델 실험을 돌린다면
이 부분만 따로 쓸 수 있다.
