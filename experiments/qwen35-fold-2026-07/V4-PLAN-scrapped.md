## B. 신설 §4.6 — 학습 없는 천장을 다시 밀다 (Qwen3.5-122B-A10B, Metal)

대상: Qwen3.5-122B-A10B (49블록 중 48논리층, 256전문가 top-8, d=3072, 하이브리드
어텐션 — 4층마다 full, 나머지 GatedDeltaNet). 혼합정밀 3.51 BPW.
프로토콜: wikitext-2 test, 16청크, c512 b512, k=6 오버라이드. 메모리 = 적재 바이트 직접 계산.

### B1. 핫 전문가 복원 (E-HOT) — §4.5 가 열어둔 문
v3 §4.5 는 게이팅측 수리를 닫으면서 "always-on 경로에 R 자체를 바꾸는 어댑터"를 열어뒀다.
이를 **원본 가중치**로 구현: 접힌 논리층마다 자기 층 게이트 질량 상위 16 전문가 + 자기
라우터 해당 열을 GGUF 수술로 되살려 always-on 가산.
`FFN = γ·MoE(대표 라우터, 대표 전문가) + δ·MoE(자기 핫16, 자기 핫 라우터) + shexp`
- δ=0 회귀가 소수점까지 일치 (구현 무결 증명)
- 결과: ppl −29% (18.99 → 13.49 @7rep). 캠페인 중 최대 단일 개선
- 설계 근거: 선행 실패(논리 라우터 단독 +57%)가 **층 간 전문가 인덱스 비호환**을 증명 →
  핫은 자기 라우터 열과 짝지어야 함

### B2. 전문가 예산 재배치 — 최대 단일 개선
메모리 회계를 교정(wired/RSS → 적재 바이트)하자 배분 실수가 드러났다.
6-rep 맵의 앞쪽 대표 0/8/15 는 **각자 자기 층 1개만** 먹이며 2.90 GiB(예산 19%)를 쓴다.
뒤쪽 대표는 하나가 7~8개를 먹인다.
- 앞쪽 전부 γ=0 으로 접고 예산을 뒤쪽 대표 3→6개로: **ppl 14.6569 → 12.1993, 메모리 15.11 GiB 동일**
- 대표 위치가 ppl 2.3 산포를 만든다(12.20~14.64). 설명 변수 후보 n_hot_absent(ρ=0.899,
  p=0.0004)는 부분 지지 — 엄격판은 반례(Q1)로 기각, 집단 평균만 유리

### B3. 벤치 전이 확정 (대응 McNemar)
같은 문항·시드이므로 누적 정답률 로그를 차분해 **문항별 정오를 복원**하고 대응 검정 적용.
비대응 비교는 검출력이 부족해 캠페인 내내 "전이 없음"으로 오판하게 만들었다.

| 벤치 | C(ppl 18.99) | A(14.66) | **Q3(12.20)** | 대응 p (기준 C) |
|---|---|---|---|---|
| HellaSwag-400 | 49.25 | 52.75 | **59.25** | **1×10⁻⁵ ✓** |
| ARC-C(299) | 34.45 | 34.78 | **40.80** | **0.018 ✓** |
| Winogrande(1267) | 61.48 | 60.38 | 64.33 | 0.14 (문항별 줄 없어 비대응) |
| MMLU(우도, 2000) | 31.90 | 33.20 | 33.36 | 0.21 |

A 단계에서는 HellaSwag p=0.098, ARC p=1.00 으로 둘 다 미달 → **개선이 임계를 넘어야
벤치에 나타난다.** 중간 지점에서 "전이 없음"으로 결론내는 것은 성급하다.

## C. 신설 §4.7 — 측정 방법론 (독립 기여)

### C1. 우도 채점이 접기 손상을 가린다
`llama-perplexity --multiple-choice` 는 정답 토큰의 상대 확률만 본다. Qwen3.5 는 thinking
기본 생성형 모델이라 실사용과 어긋난다. 동일 하네스(채팅 템플릿 + 추론 600토큰 예산강제 +
`\boxed{}` 추출, 동일 60문항):

| | 즉답 | 추론 600토큰 | 추론 효과 |
|---|---|---|---|
| 네이티브 Qwen3.5-35B-A3B | 71.7% | **81.7%** | **+10.0** |
| 접힌 122B (Q3) | 30.0% | **26.7%** | **−3.3** |
| 우연 | 25% | 25% | — |

- 35B 의 81.7% 가 공식 MMLU-Redux 93.3 과 정합 → **하네스 정상, 26.7% 는 실제 능력**
- 격차: 우도 8.2점 → **생성형 55.0점**
- **접기는 추론 누적 능력 자체를 파괴한다**: 35B 는 추론이 도움(+10.0), 접힘은 해(−3.3).
  격차도 즉답 41.7 → 추론 55.0 으로 추론을 쓸수록 벌어진다

### C2. 대응 검정
llama.cpp MC/HellaSwag 로그는 누적 정답률을 문항마다 출력한다. 이를 차분하면 문항별
정오가 복원되어 McNemar 대응 검정이 가능하다. 비대응 z 검정 대비 검출력이 크게 다르다
(HellaSwag: 비대응 z=1.86 p≈0.06 vs 대응 p=0.0005).

### C3. 네이티브 대조군 필수
같은 하네스로 네이티브 모델을 재지 않으면 "하네스 결함"과 "모델 손상"을 구분할 수 없다.
초기 생성형 프로브는 `<think>` 를 **차단**해 27%(우연 미달)를 냈고 무효였다.
또한 무제한 예산에서는 접힌 모델이 추론을 종료하지 못해 2048토큰 상한까지 소모, 답 미출력.

### C4. 질적 확인 없이 벤치만 보면 안 된다
최종 구성의 실제 생성물 확인(3문항):
- 영어("What is the capital of France?"): **정상** — 논리적 추론 + 정답, 25.7 t/s
- 한국어 2문항: `</think>` 무한 반복, 1문항은 답 자체가 없음
→ **종료 토큰 손상이 남아 있고 저빈도 언어에서 증폭된다.** 영어 벤치만으로는 안 보인다.

### C5. 속도 주장의 조건부성
보고해온 33~40 t/s 는 ngram 추측 디코딩 + `<think>` 억제 조건이다.
**순수 디코드는 15.3 t/s.** 추론이 기본인 모델이므로 실사용 체감은 후자에 가깝다.

## D. §5 논의 개정 — 주장 범위를 좁힌다

미접힘 122B 는 네이티브 35B 보다 낫다(MMLU +4.61, HellaSwag +0.25, ppl 2.41 낮음).
**그러나 접기 손실(MMLU 12.85)이 그 우위(4.61)의 3배다.**

> 같은 15 GB 예산에서 **122B 를 접어 쓰는 것보다 35B 를 그냥 양자화해 쓰는 것이 낫다.**

따라서 v4 는 주장을 좁힌다:
- 접기의 가치는 "같은 메모리에서 더 나은 성능"이 **아니다** (이 측정으로 반증됨)
- 남는 가치는 (a) 그 메모리에 원래 **안 들어가는** 모델을 구동 가능하게 만드는 것,
  (b) 저장소 절벽 제거라는 시스템 기여, (c) loop-native 학습의 사전 근거
- §3.5 사다리가 (c)를 강화한다: 회복률이 150M 에서 71%로 오르고 측정 안정성도 13.8배 좋아진다

## E. 부록 추가 — 운영 사고와 재현 인프라

1. **커널 패닉** (watchdog timeout 94초): 체인 스크립트 두 개가 같은 대기 조건을 걸어
   1초 차이로 동시 시작 → 15 GiB 모델 2개 동시 적재 → 스와핑. 가드가 자기 프로세스만 감시.
   → 전역 잠금(shlock) + 단일 순차 큐 + 시스템 전체(스왑/여유율/디스크) 감시로 구조적 해결.
2. **pgrep 자기매치** 2회: `pgrep -f "패턴"` 이 패턴 문자열을 담은 자기 셸을 매치 →
   체인 교착과 안전 감시자 오탐. → `pgrep -x`(이름 기준).
3. **while-read 루프의 stdin 도난**: 루프 내 명령이 큐 파일 fd 를 소비해 읽기 위치 파손.
   → `< /dev/null`.
4. **지연 로드 배열 되쓰기**: `mx.load` 의 mmap 배열을 들고 같은 파일에 저장하면 파일이
   먼저 잘려 아직 읽지 않은 텐서가 0 이 된다.
